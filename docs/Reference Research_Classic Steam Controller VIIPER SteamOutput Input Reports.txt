1. WHAT REMAINS VALID
===============================================================================

The Gordon work established reusable engineering contracts that survive the Steam Deck transition:

  - canonical lib/viiper is the Addon's native integration path;
  - typed native handles are preferred over generic/legacy clib ownership;
  - buses remain caller-owned after typed device removal;
  - tracked AttachUSBDevice / DetachUSBDevice ownership is explicit;
  - unknown attach/detach outcomes fail closed;
  - matching generated header and DLL must come from the same VIIPER build;
  - Addon Windows PnP identity evidence remains separate from VIIPER logical IDs;
  - recovery intent is recorded before virtual-output mutation;
  - Addon-owned output identity remains uncertain until exact PnP ownership is proven;
  - HidHide must not accidentally block the Addon-owned virtual output;
  - neutral state is published before live input begins;
  - live publisher stops before virtual-device removal;
  - teardown verifies the exact owned PnP node is gone before recovery evidence is cleared.

These are not Gordon-specific product features. Reuse them for Steam Deck.

===============================================================================
2. GORDON-SPECIFIC INPUT FINDINGS — HISTORICAL
===============================================================================

The current Gordon path uses a 64-byte Classic Steam Controller report and was adapted to MSI Claw physical controls.

Important historical Addon substitutions included:

  MSI Claw right stick -> Gordon right pad X/Y
  MSI Claw R3          -> Gordon right-pad press
  MSI Claw M2          -> Gordon Left Grip
  MSI Claw M1          -> Gordon Right Grip

The canonical Gordon state was later extended to preserve explicit digital L2/R2 full-pull state independently from analog trigger magnitude.

These mappings explain the current Gordon code and tests, but they must not be copied into the Steam Deck mapper where native right-stick, R3, and four rear-button fields already exist.

===============================================================================
3. WHY GORDON IS NO LONGER THE PRIMARY TARGET
===============================================================================

Gordon was a strong validation vehicle for the canonical embedded VIIPER lifecycle, but its logical control shape is less suitable for modern handheld PCs.

Steam Deck provides native fields for:

  right stick
  R3
  L4/R4/L5/R5
  QuickAccess
  Steam
  raw IMU

This removes several Gordon-specific translations and provides room for future handhelds with more physical rear/OEM controls.

===============================================================================
4. DO NOT DELETE THE GORDON ENGINEERING HISTORY
===============================================================================

The Addon may retire the Gordon production path only after Steam Deck hardware stability is proven.

  - delete device/steamcontroller from VIIPER;
