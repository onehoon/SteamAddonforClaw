Steam Input Addon for Claw
Reference Research — Physical Input / HidHide / MSI Claw Isolation

Original research date: 2026-08-11
Status: ACTIVE PHYSICAL-INPUT REFERENCE

===============================================================================
0. SCOPE
===============================================================================

This document records MSI Claw physical-input, topology, HidHide, and recovery
facts. It is independent of the virtual-output implementation, whose active
target is Steam Deck `VID=0x28DE`, `PID=0x1205`.

===============================================================================
1. PHYSICAL CONTROLLER CONTRACT
===============================================================================

The Addon acquires the built-in MSI Claw controller in PID_1902 DirectInput
mode.

  USB VID/PID: 0DB0:1902
  gamepad collection: HID\VID_0DB0&PID_1902&MI_00&COL01\...

The physical root and sibling collections are topology evidence and are not
blanket HidHide targets. Exact PnP identity and verified topology are required
before acquisition.

===============================================================================
2. VERIFIED CONTROL SEMANTICS
===============================================================================

  A/B/X/Y
  8-way D-pad
  LB/RB
  analog LT/RT travel
  independent LT/RT digital full-pull buttons
  left/right analog sticks
  L3/R3
  M1/M2 rear buttons

Digital trigger states remain independent from analog travel after
normalization:

  Buttons[6] -> LeftTriggerFull
  Buttons[7] -> RightTriggerFull

Rear-button side identity is preserved:

  M1 = right rear
  M2 = left rear

Output mapping is applied only after normalized state production.

===============================================================================
3. IDENTITY AND TOPOLOGY
===============================================================================

The device enumerator must resolve the expected MSI gamepad collection and its
verified physical root. VID/PID counts, friendly names, or a single matching
collection are not sufficient evidence.

Unknown or ambiguous topology fails closed. Pre-existing unrelated devices and
HidHide entries must remain untouched.

===============================================================================
4. HIDHIDE AND RECOVERY
===============================================================================

Isolation is scoped to exact Addon-owned physical identities. The Addon keeps
an explicit recovery boundary and journal so startup, suspend/resume, and
teardown can restore a safe stock state.

Unknown ownership, partial mutation, failed restoration, and residual state
remain fail-closed. The recovery path must not infer ownership from a broad
VID/PID match.

===============================================================================
5. ACTIVE OUTPUT BOUNDARY
===============================================================================

Normalized physical input is routed to the canonical Steam Deck target:

  VID=0x28DE PID=0x1205

The physical input layer remains target-neutral. Steam Deck-specific fields,
rear-button semantics, and future motion/haptic features belong in the output
mapping and dedicated feature tracks.
